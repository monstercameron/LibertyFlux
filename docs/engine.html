How the engine works

Grand Theft Auto IV runs on RAGE, Rockstar's own engine. This page shows how it is put together, from what the project has found so far in the executable and the game's files.

Nearly a third of the code is about people

The executable holds 45,229 functions. Sorted by what they work on, the largest share by far belongs to pedestrians: how they decide, react, walk and fight.

  1. People: AI tasks and events13,286
  2. Main loop, timing, locking4,419
  3. Streaming and loading4,416
  4. Files and memory3,261
  5. Physics and collision3,240
  6. Input, menus and HUD2,974
  7. Network and online2,893
  8. Script machine and natives2,863
  9. Vehicles2,586
  10. Audio2,370
  11. World and object pools1,620
  12. Animation and Euphoria1,276

Each function is assigned to the nearest subsystem whose code could be identified, so the split is approximate. The counts include the libraries built into the executable.

More than half of the classes are leaderboards

The executable declares 3,727 C++ classes. About 1,927 of them are four leaderboard templates, each stamped out once for every one of 481 multiplayer leaderboards. The largest family that does real work is the AI's 334 task classes.

  • Leaderboard templates, 1,927
  • AI tasks, 334
  • Everything else, 1,466

A pedestrian's mind is a stack of tasks

Nobody in Liberty City runs one big behaviour routine. Each person holds a goal, the goal picks a smaller step, and the step picks one action. When something happens nearby, an event arrives and can replace any level of the stack.

An event arrives A gunshot, damage, a shout. 82 kinds.
Complex task: a goal Chooses a subtask and watches it. 197 kinds.
Complex task: a step toward it Complex tasks can nest several deep.
Simple task: one action Does one thing for a few frames, then reports back. About 130 kinds.
The body moves Movement and animation, or Euphoria if the body goes limp.

The diagram shows the structure. The counts are measured from the executable's class records.

  • About 192 bytes is the typical size of a complex task. Tasks live in fixed pools, not the general heap.
  • 39 movement tasks carry a second interface so the movement system can drive them directly.
  • 18 Euphoria behaviours take over when a body turns ragdoll.
  • No "wanted level" class exists. Police response is driven by data files and scripts.

The story runs on a small stack machine

Missions are not compiled into the executable. They ship as 941 script files, run by an interpreter with 78 instructions. Scripts cannot touch the engine directly: they call named commands, called natives, and the engine does the work.

  2. PUSH 7
  3. ADD

Press Step to run the first instruction.

This three-instruction program was the first thing the project ran through the game's original interpreter code. It answered 12.

  • 14,499,370 instructions across all the shipped scripts.
  • 717,139 calls from scripts into the engine.
  • 3,034 natives are registered, and every one now has a name.
  • IS_CHAR_INJURED is the most-called native, followed by PRINTSTRING and IS_CHAR_DEAD.
  • Dividing by zero does not crash a script: the result is the number you started with.
  • 46 debug natives were stripped from the release build and now all lead to one empty function.

The city is 23.9 GB of nested containers

Almost everything sits inside archives. Inside an archive, each model, texture set or collision mesh is a compressed resource, laid out so it can be copied into memory and used without further parsing.

10.2 GB 49 archives of audio and models 10.1 GB 254 encrypted map archives 3.6 GB video and loose files
  1. ArchiveA table of contents and thousands of files. The map archives are encrypted with a key held in the executable.
  2. ResourceOne compressed file, split into a part for main memory and a part for the graphics card.
  3. ObjectA model, texture set, collision mesh or navigation mesh, ready to use once its internal pointers are fixed up.
  • 26,713 model files.
  • 10,839 navigation meshes holding 5.65 million polygons.
  • 95,137 road nodes joined by 159,902 links.
  • 15.5 million collision polygons in 9,102 shapes.
  • 10,134 shader programs, all compiled ahead of time.
  • 7 languages of text.

The project's Rust readers open every one of these file types with no failures. The model reader is checked against a sample of 112 files so far.

The clock counts in whole milliseconds

The engine reads a millisecond clock from more than 80 places and a high-resolution timer from one. The physics step follows the length of the frame, with no fixed step. At 30 frames per second a millisecond is a fine ruler. At several hundred it is not.

Start of frameEnd of frame

Each tick mark is one millisecond. Which of the two clocks paces the frame is in the code we cannot read yet, so the ruler is an illustration of the risk, not a measured cause. What is public record: players report that handling, ragdolls, helicopter rotors and ladders misbehave above 60 frames per second.

One megabyte is still dark

The first megabyte of the game's code is encrypted in the file on disk and is only decrypted when the game starts. That is about 9% of the code, and it holds some of the most central parts.

250 pages encrypted 2,424 pages readable
  • The main loop and the program's real starting point.
  • The memory allocator that every object is created through.
  • 98.8% of the virtual functions of the multiplayer replication classes.
  • 83% of the virtual functions of the core classes: file devices, memory, parsing.
  • 92 to 98% of those of the low-level graphics classes.
  • 63% of those of the AI's event classes.

The plan is to read that megabyte from the owner's running copy of the game, then repeat the analysis on it. Every number on this page comes from an entry in the devlog, where the method and the open questions are written down.
