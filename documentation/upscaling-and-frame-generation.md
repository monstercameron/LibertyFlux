# Upscaling, frame generation and ray-tracing denoising: reference

This document surveys the current upscaling, frame generation and ray-tracing denoising frameworks from NVIDIA, AMD, Intel and Apple for a new Rust Vulkan renderer targeting Windows x64, Windows on ARM64 and macOS on Apple silicon. It was researched on 2026-10-03 from vendor documentation, vendor repositories and integration guides. Every factual claim carries a link to its source: `(verified)` means the linked page was opened and read, `(inferred)` means the claim comes from a search snippet, summary or unread portion of a source.

## What the renderer must provide

All four temporal upscalers need the same class of per-frame data, though exact conventions differ per vendor:

- A low-resolution jittered HDR colour buffer rendered before most post-processing. XeSS-SR is documented as compute passes [executed before the post-processing stage](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified), DLSS takes the [raw colour buffer in HDR or LDR space](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) (inferred), and FSR requires input colour in [linear colourspace](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-ml.md) (verified).
- A depth buffer for the frame. DLSS requires [the depth buffer each evaluate call](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) (inferred); FSR, XeSS and MetalFX temporal paths all document depth inputs ([FSR](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified), [XeSS](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified), [MetalFX](https://github.com/theapplaunchers/apple-docs-for-rag/blob/HEAD/WWDC2025/api/MetalFX.md) (inferred)).
- Per-pixel motion vectors updated every frame. DLSS requires [screen-space motion vectors at 16 or 32 bits per pixel, updated each frame](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) (inferred); the other three document motion vector inputs with unread conventions (see differences table).
- A subpixel camera jitter sequence applied to the projection matrix. DLSS requires [subpixel viewport jitter with at least 16 phases, 32 or more preferred](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) (inferred); FSR, XeSS and MetalFX document their own jitter sections ([FSR](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified), [XeSS](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified), [MetalFX sample](https://developer.apple.com/metal/sample-code/) (inferred)).
- Exposure or pre-exposure values when rendering in HDR. DLSS exposes [preExposure and exposureScale options](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/include/sl_dlss.h) (verified); FSR and XeSS document [exposure](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified) and [exposure multiplier](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified) inputs.
- A reset or invalidation signal on camera cuts and resolution changes. FSR documents [camera jump cuts](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified); equivalent handling for the others is unconfirmed from the sources read.
- For frame generation: HUD-less colour plus separate UI, and a vendor-owned or vendor-driven swap chain. XeSS-FG documents [HUD-less colour, UI texture and UI composition modes with a proxy swap chain](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified); FSR frame generation ships a [replacement DXGI swap chain for DX12](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified); DLSS frame generation routes presentation through [Streamline's DLSS-G proxy swap chain](https://github.com/thierbig/bg3fgvk/blob/HEAD/docs/2026-08-27-fgvk-design.md) (inferred).
- Mipmap biasing for sampled textures under upscaling. FSR and XeSS both document [mipmap biasing](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified) ([mip bias](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified)); DLSS and MetalFX equivalents are unconfirmed.
- Replacement of the built-in TAA pass, since temporal upscalers supersede it. Godot uses [FSR2 at scale 1.0 as a TAA solution](https://docs.godotengine.org/en/stable/classes/class_viewport.html) (inferred); FSR documents a [temporal antialiasing section](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified).

## NVIDIA DLSS

### Components and current version

- DLSS Super Resolution outputs higher-resolution frames from lower-resolution input using multiple prior frames, motion data and a transformer model ([source](https://developer.nvidia.com/rtx/dlss) (verified)).
- DLSS Frame Generation generates interpolated frames, and Multi Frame Generation generates [up to five frames per rendered frame on GeForce RTX 50 series and RTX PRO Blackwell GPUs with fifth-generation Tensor Cores](https://developer.nvidia.com/rtx/dlss) (verified).
- Dynamic Multi Frame Generation [dynamically adjusts the generation multiplier](https://developer.nvidia.com/rtx/dlss) (verified) and is part of DLSS 4.5 with a second-generation transformer model ([source](https://developer.nvidia.com/rtx/dlss) (verified)); DLSS 4 introduced MFG and the first transformer model ([source](https://developer.nvidia.com/rtx/dlss) (verified)).
- DLSS Ray Reconstruction [replaces hand-tuned denoisers with an AI network that generates pixels between sampled rays](https://developer.nvidia.com/rtx/dlss) (verified).
- DLAA applies [the same Super Resolution technology at native resolution as AI anti-aliasing](https://developer.nvidia.com/rtx/dlss) (verified), and appears as a mode alongside the upscaling modes in the Streamline header ([source](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/include/sl_dlss.h) (verified)).
- NVIDIA Reflex is the latency-reduction companion linked from the DLSS page ([source](https://developer.nvidia.com/rtx/dlss) (verified)); Reflex is [required for DLSS Frame Generation and turns on automatically with it](https://github.com/NVIDIA-RTX/Streamline/raw/refs/heads/main/docs/RTX%20UI%20Developer%20Guidelines.pdf?download=) (inferred).
- The current DLSS SDK is [version 310.9.1, published 2026-09-08](https://github.com/NVIDIA/DLSS/releases/expanded_assets/v310.9.1) (verified), and the current Streamline SDK is [version 2.14.1, published 2026-09-08](https://github.com/NVIDIA-RTX/Streamline/releases/expanded_assets/v2.14.1) (verified).
- DLSS 5 exists: NVIDIA's September 2026 developer blog describes [DLSS 5 with 3D-guided neural rendering](https://developer.nvidia.com/blog/whats-new-for-game-developers-dlss-5-with-3d-guided-neural-rendering-nvidia-ace-updates-and-new-rtx-kit-capabilities/) (verified), operating [one frame in, one frame out on engine motion vectors, locally on RTX 50 series GPUs at up to 4K](https://developer.nvidia.com/blog/whats-new-for-game-developers-dlss-5-with-3d-guided-neural-rendering-nvidia-ace-updates-and-new-rtx-kit-capabilities/) (verified), with [model selection, structure and tone intensity controls and semantic masking](https://developer.nvidia.com/blog/whats-new-for-game-developers-dlss-5-with-3d-guided-neural-rendering-nvidia-ace-updates-and-new-rtx-kit-capabilities/) (verified). It reportedly [launched 2026-09-03 with NBA 2K27 as the first title](https://tech-insider.org/nvidia-dlss-5-siggraph-2026/) (inferred), and an [RTX 40 update with a reduced feature set was reported](https://tech-insider.org/nvidia-dlss-5-rtx-40-gpus-no-full-control-2026/) (inferred). The developer DLSS page read for this research describes up to DLSS 4.5 and does not mention DLSS 5 ([source](https://developer.nvidia.com/rtx/dlss) (verified)), so SDK availability of the neural rendering runtime is unconfirmed.

### Platforms and requirements

- DLSS Super Resolution supports [DirectX 11, DirectX 12 and Vulkan, with Vulkan 1.1 or later](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) (inferred).
- DLSS Frame Generation supports [DirectX 12 and Vulkan through Streamline](https://github.com/silynometa/dlssg_for_sm86/blob/HEAD/docs/INSTALL.en.md) (inferred); driver-based Smooth Motion frame generation supports [Vulkan on RTX 50 x86-64](https://www.khronos.org/news/permalink/nvidia-adds-vulkan-support-to-smooth-motion-frame-generation-a-boost-for-many-games-and-emulators) (inferred).
- Streamline requires [Windows 10 20H1 or newer, NVIDIA driver 512.15 or newer, and a GPU with DirectX 11 and Vulkan 1.2 or higher](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/README.md) (verified).
- Linux is supported at least for the DLSS sample: the SDK release ships [separate Windows and Linux demo archives](https://github.com/NVIDIA/DLSS/releases/expanded_assets/v310.9.1) (verified).
- Windows x64 is supported ([source](https://github.com/NVIDIA-RTX/Streamline/releases/expanded_assets/v2.14.1) (verified)). Windows on ARM64: Streamline ships [aarch64 and arm64ec SDK archives](https://github.com/NVIDIA-RTX/Streamline/releases/expanded_assets/v2.14.1) (verified) and builds for [amd64, arm64 and arm64ec](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/README.md) (verified), but DLSS itself is [reported as not supported on Windows ARM64](https://videocardz.com/newz/nvidia-rtx-neural-texture-compression-adds-windows-arm64-support-for-rtx-spark) (inferred), so the ARM64 archives presumably cover the framework and non-DLSS plugins; this division is unconfirmed from a primary source.
- All DLSS components require [NVIDIA RTX GPUs with Tensor Cores](https://developer.nvidia.com/rtx/dlss) (verified); MFG additionally requires RTX 50 series or Blackwell ([source](https://developer.nvidia.com/rtx/dlss) (verified)); plain frame generation is [reported to require RTX 40 series or newer](https://github.com/noplace/psxemu/blob/HEAD/Docs/DLSS-Plan.md) (inferred). No macOS support was found in the sources read (inferred).

### Inputs

- Each DLSS-SR evaluate call takes [raw HDR or LDR colour, screen-space motion vectors, depth and an exposure value](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) (inferred).
- Jitter must be [subpixel viewport jitter with at least 16 phases, 32 or more preferred](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) (inferred).
- The Streamline DLSS options struct carries [mode, output width and height, pre-exposure, exposure scale, an HDR colour flag and per-mode presets](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/include/sl_dlss.h) (verified).
- Modes are [Off, MaxPerformance, Balanced, MaxQuality, UltraPerformance, UltraQuality and DLAA](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/include/sl_dlss.h) (verified); presets J and K are [transformer-based, with K the default quality choice](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/include/sl_dlss.h) (verified), while L and M are [defaults for UltraPerformance and Performance](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/include/sl_dlss.h) (verified).
- Frame generation additionally needs [Reflex, a Streamline-owned swap chain, a HUD-less picture or UI mask, and hardware GPU scheduling](https://github.com/noplace/psxemu/blob/HEAD/Docs/DLSS-Plan.md) (inferred). Ray Reconstruction inputs are unconfirmed; only its [integration guide filename](https://api.github.com/repos/NVIDIA/DLSS/contents/doc) (verified) was confirmed.
- Resource formats, resolution limits and dynamic-resolution rules are unconfirmed from the sources read.

### Integration outline

1. Download a Streamline release archive, since [binaries are not in the repository and must come from the releases page](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/README.md) (verified).
2. Integrate through Streamline rather than NGX, per NVIDIA's [get started with DLSS through Streamline](https://developer.nvidia.com/rtx/dlss) (verified) guidance; Streamline provides [one integration for multiple vendors' super resolution](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/README.md) (verified). The older path is the [NGX interface](https://videocardz.com/newz/modder-gets-nvidia-dlss-working-in-a-web-browser) (inferred).
3. Configure the DLSS mode, output size, exposure values and presets via the documented options ([source](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/include/sl_dlss.h) (verified)).
4. Supply colour, motion vectors, depth and exposure every frame, and drive the jitter sequence ([source](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) (inferred)).
5. For frame generation, enable Reflex and hand presentation to the Streamline swap chain ([sources](https://github.com/NVIDIA-RTX/Streamline/raw/refs/heads/main/docs/RTX%20UI%20Developer%20Guidelines.pdf?download=) (inferred), ([source](https://github.com/thierbig/bg3fgvk/blob/HEAD/docs/2026-08-27-fgvk-design.md) (inferred)).
6. Ship [production builds with NVIDIA-signed DLLs or a custom signing check](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/README.md) (verified).

### Licence and redistribution

- The DLSS SDK is governed by the [NVIDIA RTX SDKs licence](https://raw.githubusercontent.com/NVIDIA/DLSS/main/LICENSE.txt) (verified), which grants [installation and use, modification of sample source, and distribution of SDK software and materials in object form inside an application](https://raw.githubusercontent.com/NVIDIA/DLSS/main/LICENSE.txt) (verified).
- Redistribution requires [material additional functionality beyond the SDK portions, an NVIDIA source notice in derivatives, and downstream terms at least as protective](https://raw.githubusercontent.com/NVIDIA/DLSS/main/LICENSE.txt) (verified); the SDK [may not be distributed standalone or sublicensed](https://raw.githubusercontent.com/NVIDIA/DLSS/main/LICENSE.txt) (verified), and [reverse engineering is prohibited](https://raw.githubusercontent.com/NVIDIA/DLSS/main/LICENSE.txt) (verified).
- An open-source game may therefore bundle the nvngx DLLs inside its own application distribution under those terms, but may not republish the SDK itself (verified from the licence terms above). Streamline headers are [MIT-style permissive](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/include/sl_dlss.h) (verified), while the DLSS-G plugin is [prebuilt DLLs only](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/README.md) (verified).

### Pitfalls

- Default presets [may change after an over-the-air update](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/include/sl_dlss.h) (verified), so pin presets deliberately.
- The in-header sharpening control is [deprecated and unsupported](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/include/sl_dlss.h) (verified).
- Only the DLSS-G plugin [cannot be rebuilt from source](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/README.md) (verified); everything else in Streamline can be, though shipping the signed binaries is the norm ([source](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/README.md) (verified)).
- Motion vectors must be [accurate and refreshed every frame](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) (inferred); Reflex [should be unavailable when a non-NVIDIA frame generation technology is active](https://github.com/NVIDIA-RTX/Streamline/raw/refs/heads/main/docs/RTX%20UI%20Developer%20Guidelines.pdf?download=) (inferred).

## AMD FSR

### Components and current version

- The current kit is the [AMD FSR SDK 2.3.0, codenamed Redstone, released 2026-06-24](https://api.github.com/repos/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/releases/latest) (verified), described in its own readme ([source](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified)).
- Redstone is an [umbrella name for four machine-learning features: upscaling, frame generation, ray regeneration and radiance caching](https://tech-insider.org/amd-fsr-redstone-setup-2026/) (inferred).
- The SDK contains [FSR Temporal 2.3.4, FSR Upscaler 3.1.5, FSR ML upscaler 4.1.1, FSR Frame Generation 3.1.6, FSR FG SwapChain 3.1.7, FSR FG ML 4.0.1, FSR Ray Regeneration 1.2.0 and FSR Radiance Caching preview](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified).
- FSR 4 upscaling [uses machine learning over temporal and spatial information](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-ml.md) (verified) and requires [HLSL compute shader model 6.6](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-ml.md) (verified), while FSR 3.1 requires [CS 6.2, or 6.6 on 64-wide-wavefront hardware](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified).
- Both FSR 3.1 and FSR 4 expose [NativeAA 1.0x, Quality 1.5x, Balanced 1.7x, Performance 2.0x and Ultra Performance 3.0x presets](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified) ([FSR 4 source](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-ml.md) (verified)).
- Ray Regeneration 1.2.0 added [ambient occlusion and specular occlusion denoising, checkerboard rendering support and new debug controls](https://api.github.com/repos/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/releases/latest) (verified), with [API-breaking struct changes](https://api.github.com/repos/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/releases/latest) (verified).
- Integration goes through the [FSR API of five functions: ffxCreateContext, ffxDestroyContext, ffxDispatch, ffxQuery and ffxConfigure](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/getting-started/ffx-api.md) (verified), using [signed DLLs split per effect type since SDK 2.0](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/getting-started/ffx-api.md) (verified): loader, upscaler, frame generation, denoiser and radiance cache ([source](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/getting-started/ffx-api.md) (verified)).

### Platforms and requirements

- The SDK targets [DirectX 12 or Vulkan applications](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified), and its samples run on [DirectX 12 and Vulkan](https://github.com/matheusgviana/dlss-5-amd-project/blob/HEAD/OptiScaler-DLSSNR-PreSR-Multipass-main/external/FidelityFX-SDK/docs/getting-started/index.md) (inferred).
- Backend-specific FSR API functionality is [currently only supported for DirectX 12](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/getting-started/ffx-api.md) (verified), and the ML SDK releases target [DirectX 12 on Windows 10 and 11](https://videocardz.com/newz/amd-launches-fsr-sdk-2-1-0-to-speed-up-adoption-of-fsr-redstone) (inferred), so Vulkan coverage of the ML components is unconfirmed.
- Windows x64 is supported ([source](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified)). Windows on ARM64: FSR is [reported working on Snapdragon X Elite](https://www.pcgamer.com/hardware/gaming-laptops/qualcomms-new-windows-pc-chip-supports-amds-fsr-and-im-not-sure-amd-had-any-idea-about-it/) (inferred), but prebuilt FidelityFX libraries are [reported x86-64 only, needing a source rebuild for arm64ec](https://github.com/justradical/sloptiscaler/blob/HEAD/arm64ec/README.md) (inferred). macOS support is unconfirmed from the sources read.
- Analytical FSR 2/3 upscaling is vendor-agnostic, listed for [Radeon RX 500 series and above or equivalents](https://videocardz.com/newz/amd-releases-fsr-sdk-2-2-with-fsr-upscaling-4-1-and-fsr-ray-regeneration-1-1) (inferred), with frame generation 3.1.6 listed for [RX 5000 series and newer](https://videocardz.com/newz/amd-releases-fsr-sdk-2-2-with-fsr-upscaling-4-1-and-fsr-ray-regeneration-1-1) (inferred).
- FSR 4 ML upscaling officially supports [RDNA4 over FP8 and RDNA3 over INT8, with RDNA2 planned for 2027](https://github.com/characterecho-sean/edvr-unofficial-patch/blob/HEAD/docs/fsr-upscaler-design-2026-09-16.md) (inferred), falling back to [FSR 3.1.5 on other hardware](https://github.com/characterecho-sean/edvr-unofficial-patch/blob/HEAD/docs/fsr-upscaler-design-2026-09-16.md) (inferred).

### Inputs

- FSR upscaling takes [input colour, depth with several buffer configurations, motion vectors, a reactive mask, a transparency and composition mask, and exposure](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified), plus [camera jitter, jump-cut handling, mipmap bias and frame time delta](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified). Exact vector, depth and jitter conventions sit in unread portions of that document and are unconfirmed.
- Input colour must be in [linear colourspace](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-ml.md) (verified); otherwise the [FFX_UPSCALE_ENABLE_NON_LINEAR_COLORSPACE creation flag](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-ml.md) (verified) can be set with possible quality cost ([source](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-ml.md) (verified)).
- Reactivity can be [generated automatically as well as supplied](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified).
- Frame generation consumes [multiple real frames and multiple motion vector sources](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified); its detailed inputs were not read and are unconfirmed.
- Placement relative to tone mapping and UI, formats and resolution limits sit in [documented but unread sections](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified) and are unconfirmed.

### Integration outline

1. Choose the analytical source path or the ML signed-binary path; FSR 4 [requires the FSR API and the signed binary distribution](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-ml.md) (verified).
2. Load the loader DLL at runtime and let it pull in only the effect DLLs used, since the split [lets applications ship only the effect types they use](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/getting-started/ffx-api.md) (verified); applications on the old combined DLL [must switch to the loader DLL](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/getting-started/ffx-api.md) (verified).
3. Drive effects through the five API functions with chained descriptor structs ([source](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/getting-started/ffx-api.md) (verified)).
4. Supply colour, depth, motion vectors, masks and exposure, and implement jitter, cut handling, mip bias and frame delta ([source](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified)).
5. For frame generation on DirectX 12, adopt the [replacement DXGI swap chain implementation](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified); the Vulkan frame generation story is unconfirmed.
6. Validate with the SDK's upscaling, frame generation, denoiser and radiance cache samples ([source](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified)).

## Intel XeSS

### Components and current version

- The current kit is the [XeSS 3 SDK, latest release 3.0.2 published 2026-07-24](https://api.github.com/repos/intel/xess/releases/latest) (verified), with the repository describing itself as the XeSS 3 SDK ([source](https://raw.githubusercontent.com/intel/xess/main/README.md) (verified)).
- XeSS Super Resolution boosts frame rates on [all GPUs with SM 6.4 DP4a support](https://raw.githubusercontent.com/intel/xess/main/README.md) (verified).
- XeSS Frame Generation targets [Intel Arc discrete and integrated GPUs plus non-Intel GPUs with SM 6.4](https://raw.githubusercontent.com/intel/xess/main/README.md) (verified); since 2.1 it uses [common Shader Model 6.4 code on non-Intel GPUs](https://www.phoronix.com/news/Intel-XeSS-2-1-Released) (inferred).
- Xe Low Latency is available on [Arc GPUs and on non-Intel GPUs when combined with XeSS-FG](https://raw.githubusercontent.com/intel/xess/main/README.md) (verified); standalone XeLL is [not supported on non-Intel GPUs](https://www.phoronix.com/news/Intel-XeSS-2-1-Released) (inferred).
- XeSS-FG [requires XeLL integration, while SR and XeLL can each be enabled independently](https://raw.githubusercontent.com/intel/xess/main/README.md) (verified).
- Release 3.0.2 updated XeLL to 1.3.2.10, fixing [minimumIntervalUs units, a non-Intel memory leak and Streamline proxy handling](https://api.github.com/repos/intel/xess/releases/latest) (verified).

### Platforms and requirements

- XeSS-SR supports [DirectX 11, DirectX 12 and Vulkan](https://www.intel.com/content/www/us/en/developer/articles/technical/xess2-whitepaper.html) (inferred), with [API-specific initialisation and execution paths for all three](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified) and a [Vulkan 1.1 requirement](https://www.intel.com/content/www/us/en/developer/articles/technical/xess-sr-developer-guide.html) (inferred).
- XeSS-FG and XeLL are [designed for DirectX 12](https://www.intel.com/content/www/us/en/developer/articles/technical/xess2-whitepaper.html) (inferred); the FG guide requirements list [Windows 10/11 x64 and DirectX 12 with Intel driver 32.0.101.7029 or later on Arc and Core Ultra families](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified). Frame generation on Vulkan is [reported as unsupported](https://github.com/peqhub/mcvr/blob/HEAD/docs/XeFG_Research_Report.md) (inferred).
- Operating system support is [Windows 10/11 x64](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified); the stack is described as [Windows-focused](http://www.phoronix.com/news/Intel-XeSS-SDK-2.0.1) (inferred). Windows on ARM64 is not documented and the x64-only requirements imply it is unsupported (inferred); no Linux or macOS support was found in the sources read (inferred).
- Quality presets run [NativeAA 1.0x, Ultra Quality Plus 1.3x, Ultra Quality 1.5x, Quality 1.7x, Balanced 2.0x, Performance 2.3x and Ultra Performance 3.0x](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified).

### Inputs

- XeSS-SR takes [jitter with a defined sequence, colour, motion vectors, depth, a responsive pixel mask and mip bias settings](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified), with [jitter scale, velocity scale and exposure multiplier controls](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified) and [fixed and dynamic input resolution modes](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified). Exact vector, depth and jitter conventions sit in unread portions and are unconfirmed.
- Resource states and formats are [documented per API including Vulkan specifics](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified); details are unconfirmed here.
- XeSS-FG takes [motion vectors, depth, HUD-less colour and a UI texture with resource tagging and frame constants](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified), plus [UI composition modes, HDR display support and letterboxing handling](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified).
- Frame rate targets are [40 FPS minimum and 60 FPS recommended input](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified); all [VSync and fixed or variable refresh modes are supported](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified).
- Super resolution runs [before post-processing](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified); frame generation runs [before presentation through a proxy swap chain issuing several presents per rendered frame](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified).
- XeLL works through [sleep calls and simulation, render-submit and present markers](https://raw.githubusercontent.com/intel/xess/main/doc/xell_developer_guide_english.md) (verified), reducing [input-to-render and render-to-screen latency](https://raw.githubusercontent.com/intel/xess/main/doc/xell_developer_guide_english.md) (verified).

### Integration outline

1. Integrate in the recommended order: [SR first, then XeLL, then FG](https://raw.githubusercontent.com/intel/xess/main/README.md) (verified).
2. Initialise SR on the DX11, DX12 or Vulkan path and query [required instance and device extensions and features on Vulkan](https://www.intel.com/content/www/us/en/developer/articles/technical/xess-sr-developer-guide.html) (inferred).
3. Supply the per-frame inputs and scales each dispatch ([source](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified)).
4. Add XeLL sleep and markers around simulation, submission and present ([source](https://raw.githubusercontent.com/intel/xess/main/doc/xell_developer_guide_english.md) (verified)).
5. Add FG with its [proxy swap chain, external heap options, generated-frame count control and UI handling](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified); handle [window and swap chain resolution changes and present status](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified).
6. Verify with the [XeSS Inspector debugging tool](https://raw.githubusercontent.com/intel/xess/main/README.md) (verified).

## Apple MetalFX

### Components and current version

- MetalFX offers [spatial upscaling from colour alone and temporal upscaling from colour, depth and motion](https://github.com/theapplaunchers/apple-docs-for-rag/blob/HEAD/WWDC2025/api/MetalFX.md) (inferred), via the MTLFXSpatialScaler and MTLFXTemporalScaler effect classes ([source](https://github.com/theapplaunchers/apple-docs-for-rag/blob/HEAD/WWDC2025/api/MetalFX.md) (inferred)).
- Frame interpolation [generates intermediate frames for higher refresh rates](https://dev.to/arshtechpro/wwdc-2025-discover-metal-4-23f2) (inferred) and runs [at the end of the pipeline just before display](https://HotHardware.com/news/apple-unveils-metalfx-frame-interpolation-ai-game-rendering-bandwagon) (inferred).
- The denoised temporal scaler [removes noise from low ray-count renders during upscaling](https://github.com/need2edit/wwdc-journal/blob/HEAD/analysis/essentials-accessibility-media-games.md) (inferred), aimed at [practical ray and path tracing on Apple hardware](https://www.flatpanelshd.com/news.php?subaction=showfull&id=1749809641) (inferred).
- Metal 4 adds MTL4FX-prefixed variants of all four effects, confirmed by the [feature list of the Rust MetalFX bindings](https://crates.io/api/v1/crates/objc2-metal-fx) (verified).
- MetalFX is an OS framework without SDK versions; the [MetalFX documentation root](https://developer.apple.com/documentation/metalfx) (verified) resolved but returned only a script shell, so class details below come from snippets and mirrors.

### Platforms and requirements

- MetalFX upscaling arrived with [macOS Ventura](https://www.techpowerup.com/295612/apple-announces-macos-ventura-with-new-productivity-gaming-features&lt) (inferred); frame interpolation and denoising arrived with [Metal 4 on macOS Tahoe 26](https://www.tomshardware.com/software/macos/apple-debuts-macos-26-tahoe-at-wwdc-with-liquid-glass-redesign) (inferred). Whether the non-Metal-4 interpolator and denoiser classes work on older systems is disputed in [developer discussion](https://forums.macrumors.com/threads/major-gaming-news-at-wwdc-metal-and-new-games.2347213/page-198) (inferred) and unconfirmed.
- Hardware needs an [M1 minimum on Apple silicon](https://www.tweaktown.com/news/86706/metalfx-upscaling-apples-take-on-nvidia-dlss-amd-fsr-intel-xess/index.html) (inferred); exact per-effect GPU tiers are unconfirmed.
- There is no Windows support; MetalFX is Apple-platform only (inferred). Reaching it from a Vulkan application on MoltenVK requires exporting the underlying Metal objects through [VK_EXT_metal_objects, which exposes vkExportMetalObjectsEXT and Metal-backed VkDeviceMemory, VkImage, VkSemaphore and VkEvent](https://raw.githubusercontent.com/KhronosGroup/Vulkan-Docs/main/appendices/VK_EXT_metal_objects.adoc) (verified) on [Metal-layered implementations only](https://raw.githubusercontent.com/KhronosGroup/Vulkan-Docs/main/appendices/VK_EXT_metal_objects.adoc) (verified).
- Community attempts show the interop is fragile: one project reports [running MetalFX over exported MoltenVK textures could never work because MoltenVK presents after the hook runs](https://github.com/hongyuehao123/metalmod/blob/HEAD/docs/phase7-plan.md) (inferred), while another design [exports the low-resolution texture and queue and presents the MetalFX result in a native overlay](https://github.com/zinedinarnaut/sol/blob/HEAD/Docs/SOL_ENGINE_ARCHITECTURE.md) (inferred). No official Vulkan-to-MetalFX path was found; a native Metal renderer is the documented route (inferred).

### Inputs

- The temporal scaler needs [pixel colour, depth and motion information](https://github.com/theapplaunchers/apple-docs-for-rag/blob/HEAD/WWDC2025/api/MetalFX.md) (inferred); the spatial scaler needs [only colour](https://github.com/theapplaunchers/apple-docs-for-rag/blob/HEAD/WWDC2025/api/MetalFX.md) (inferred).
- Apple's sample shows [adding jitter during rendering and building a motion vector texture](https://developer.apple.com/metal/sample-code/) (inferred); the sample page resolved but its content was not reached (verified).
- Frame interpolation accepts [camera parameters and elapsed time between frames](https://HotHardware.com/news/apple-unveils-metalfx-frame-interpolation-ai-game-rendering-bandwagon) (inferred).
- The denoised scaler path is reported to need [separate colour, depth, motion, albedo, normal and roughness textures](https://github.com/tqjxlm/sparkle/blob/HEAD/docs/Denoiser.md) (inferred).
- Vector, depth and jitter conventions, formats and resolution rules are unconfirmed from primary sources.

### Integration outline

1. Pick [spatial or temporal upscaling based on available inputs](https://github.com/theapplaunchers/apple-docs-for-rag/blob/HEAD/WWDC2025/api/MetalFX.md) (inferred).
2. Render low resolution with jitter and produce depth and motion vector textures ([source](https://developer.apple.com/metal/sample-code/) (inferred)).
3. Configure the matching descriptor and effect, then encode it on the Metal command buffer (inferred from the class model; details unconfirmed).
4. Add frame interpolation late in the frame with camera and timing data ([source](https://HotHardware.com/news/apple-unveils-metalfx-frame-interpolation-ai-game-rendering-bandwagon) (inferred)).
5. For path tracing, route the ray-traced buffers through the denoised scaler ([source](https://github.com/need2edit/wwdc-journal/blob/HEAD/analysis/essentials-accessibility-media-games.md) (inferred)).
6. On MoltenVK, export Metal objects per the extension ([source](https://raw.githubusercontent.com/KhronosGroup/Vulkan-Docs/main/appendices/VK_EXT_metal_objects.adoc) (verified)) and own Metal presentation and cross-queue synchronisation yourself; expect [explicit MTLSharedEvent ordering work](https://github.com/hongyuehao123/metalmod/blob/HEAD/ROADMAP.md) (inferred).

### Licence and redistribution

- MetalFX ships with Apple operating systems under Apple developer terms; there are no redistributable binaries, DLLs or headers to ship (inferred). Exact licence text was not reviewed and is unconfirmed.

### Pitfalls

- The Metal 3 versus Metal 4 class split (MTLFX versus MTL4FX) is confirmed by [binding feature flags](https://crates.io/api/v1/crates/objc2-metal-fx) (verified) but version gating per class is unconfirmed; verify availability macros before use.
- Temporal state must be reset on camera and world transitions; at least one engine [invalidates MetalFX history, exposure feedback and motion history together](https://github.com/mbrock/moppe/blob/HEAD/docs/renderer-design.md) (inferred).
- Output textures are reported to require [private storage mode](https://github.com/havokentity/demont-engine/commit/24328c9b6613951e17ad40f3a9c98fe6efa490b0) (inferred).
- Early OS releases had [fixed bugs in MTL4FX denoised and temporal upscaling](https://github.com/averyy/apple-dev-docs/blob/HEAD/documentation/macos-release-notes/macos-26-release-notes.md) (inferred); pin minimum OS versions deliberately.

## Ray tracing and path tracing support

- DLSS Ray Reconstruction is the NVIDIA denoiser: an [AI network replacing hand-tuned denoisers between sampled rays](https://developer.nvidia.com/rtx/dlss) (verified), with transformer architecture in its Streamline plugin ([source](https://developer.nvidia.com/rtx/dlss) (verified)). It needs an RTX GPU ([source](https://developer.nvidia.com/rtx/dlss) (verified)); detailed inputs are unconfirmed.
- FSR Ray Regeneration 1.2.0 is the AMD ML denoiser ([source](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified)), now covering [ambient occlusion, specular occlusion and checkerboard rendering](https://api.github.com/repos/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/releases/latest) (verified). FSR Radiance Caching is a [technical preview for caching path tracing results](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified), at [version 0.9.0](https://tech-insider.org/amd-fsr-redstone-setup-2026/) (inferred).
- Intel has no ray-tracing denoiser in the XeSS SDK as far as the sources read show; only [SR, FG and low latency are listed](https://raw.githubusercontent.com/intel/xess/main/README.md) (verified).
- MetalFX denoising is the Apple path for [low ray-count and path-traced content](https://www.flatpanelshd.com/news.php?subaction=showfull&id=1749809641) (inferred), demonstrated with [real-time path tracing](https://www.pcquest.com/news/mac-gaming-2026-apple-gaming-metal-4-game-porting-toolkit-12004351) (inferred).
- MoltenVK does not support Vulkan ray tracing in any release: it is an [almost-complete subset of Vulkan 1.4](https://raw.githubusercontent.com/KhronosGroup/MoltenVK/main/README.md) (verified), and ray tracing exists only as [open, unmerged pull request 2771 implementing the KHR acceleration structure, ray query, ray tracing pipeline, pipeline library and maintenance1 extensions behind an experimental flag](https://api.github.com/repos/KhronosGroup/MoltenVK/pulls/2771) (verified), created 2026-07-12 and still open ([source](https://api.github.com/repos/KhronosGroup/MoltenVK/pulls/2771) (verified)). Third parties confirm the [KHR ray extensions are absent from MoltenVK devices](https://github.com/tagban/moghouse/blob/HEAD/docs/macos-bringup.md) (inferred). Consequence: path tracing on macOS needs native Metal, not MoltenVK Vulkan RT.

## One interface for all four

- A shared abstraction can own the common inputs: render and display resolutions, jitter generation and projection updates, depth and motion vector production, exposure tracking, cut resets, mip bias and the UI split for frame generation, since every framework consumes this class of data ([DLSS](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) (inferred), [FSR](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/Kits/FidelityFX/docs/techniques/super-resolution-upscaler.md) (verified), [XeSS](https://raw.githubusercontent.com/intel/xess/main/doc/xess_sr_developer_guide_english.md) (verified), [MetalFX](https://github.com/theapplaunchers/apple-docs-for-rag/blob/HEAD/WWDC2025/api/MetalFX.md) (inferred)). Godot's single [scaling mode enum over FSR and MetalFX](https://docs.godotengine.org/en/stable/classes/class_viewport.html) (inferred) and OptiScaler's [per-API upscaler selection](https://github.com/gabrielmaialva33/optiscaler_dlssnr/blob/HEAD/Config.md) (inferred) show the pattern is viable.
- What cannot be unified: graphics API coverage, since [XeSS frame generation is DirectX 12 only](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified) and MetalFX is Metal only (inferred); swap chain ownership, since DLSS-G, FSR and XeSS each impose [their own proxy or replacement swap chain](https://github.com/thierbig/bg3fgvk/blob/HEAD/docs/2026-08-27-fgvk-design.md) (inferred) ([FSR](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/main/readme.md) (verified), [XeSS](https://raw.githubusercontent.com/intel/xess/main/doc/xess_fg_developer_guide_english.md) (verified)); hardware gating, since DLSS needs [RTX](https://developer.nvidia.com/rtx/dlss) (verified), FSR 4 ML needs [RDNA3/4](https://github.com/characterecho-sean/edvr-unofficial-patch/blob/HEAD/docs/fsr-upscaler-design-2026-09-16.md) (inferred) and MetalFX needs [Apple silicon](https://www.tweaktown.com/news/86706/metalfx-upscaling-apples-take-on-nvidia-dlss-amd-fsr-intel-xess/index.html) (inferred); and latency companions, since [Reflex must not be active under foreign frame generation](https://github.com/NVIDIA-RTX/Streamline/raw/refs/heads/main/docs/RTX%20UI%20Developer%20Guidelines.pdf?download=) (inferred) while [XeSS-FG mandates XeLL](https://raw.githubusercontent.com/intel/xess/main/README.md) (verified).
- Practical consequence for the stated targets: on Windows x64 all of DLSS, FSR and XeSS-SR are candidates with FG available from DLSS and FSR; on Windows ARM64 only the portable FSR path looks plausible and needs a source rebuild ([sources](https://www.pcgamer.com/hardware/gaming-laptops/qualcomms-new-windows-pc-chip-supports-amds-fsr-and-im-not-sure-amd-had-any-idea-about-it/) (inferred), ([source](https://github.com/justradical/sloptiscaler/blob/HEAD/arm64ec/README.md) (inferred)); on macOS only MetalFX applies, most robustly behind a native Metal renderer given the [fragile MoltenVK interop reports](https://github.com/hongyuehao123/metalmod/blob/HEAD/docs/phase7-plan.md) (inferred).
